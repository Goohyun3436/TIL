- 처음에는 원본 이미지 품질이 낮은 줄 알았지만, 실제로는 <strong>카페24가 대표이미지 등록 시 용도별 이미지 크기를 자동 리사이징해서 저장하는 과정에서 일부 이미지가 예상보다 작게 생성된 문제</strong>였다.

- 이번 정리는 대표이미지 등록 후 상품 이미지 해상도가 깨지는 원인과, 이미지 사이즈 변경 설정 및 개별이미지 재등록으로 복구한 과정을 기록한 내용이다.

<br />

## 문제 상황

카페24에서 상품을 등록하고 대표이미지를 올리면, 관리화면에서는 하나의 이미지를 넣은 것처럼 보여도 실제로는 상세 이미지, 목록 이미지, 작은목록 이미지, 축소 이미지처럼 여러 목적의 이미지가 각각 생성된다.

<strong>문제는 이 자동 생성 과정에서 어떤 상품은 의도한 크기로 저장되지 않고, 특정 용도의 이미지가 지나치게 작은 해상도로 저장되는 경우가 있다는 점</strong>이었다.

예를 들면 아래처럼 이해할 수 있었다.

- 목록 이미지는 원래 300 기준으로 보여야 하는데, 실제 저장된 값은 100 수준처럼 작게 들어간 경우

즉, <strong>카페24 서버가 상품 이미지 목적별로 자동 리사이징해서 저장하는 과정에서 예상과 다르게 생성된 것</strong>이 원인이었다.

<br />

## 대표이미지 자동 리사이징 문제

<img width="100%" alt="Image" src="https://github.com/user-attachments/assets/4bd9f3c0-d184-406f-8623-aa9a4446d893" />

관리화면 안내를 보면 카페24는 <strong>대표이미지 등록 시, 하나의 이미지를 기준으로 상세 이미지, 목록 이미지, 작은목록 이미지, 축소 이미지 등을 각각 리사이징해서 등록</strong>한다.

<img width="100%" alt="Image" src="https://github.com/user-attachments/assets/7e0ed5e4-db8d-4fd9-8e82-7b89d8aaaa3c" />

이 구조 자체는 편리하지만, 이미지 사이즈 설정값과 실제 생성 결과가 어긋나면, 이후 화면에서 이미지의 화질이 저하된 것 처럼 보이게 된다.

<img width="300" alt="Image" src="https://github.com/user-attachments/assets/a3cefd1b-eeaa-4896-a5cb-09687210fae8" />

실제로 개발자 도구로 렌더링되고 있는 갤러리의 깨진 사진 요소를 확인해보면 <strong>렌더링 사이즈(Rendered size)보다 원본 사이즈(Intrinsic size)가 더 작은 것을 확인</strong>할 수 있다.

즉, 상품 갤러리 해상도 문제는 프론트 CSS 보다는 <strong>관리자 이미지 생성 단계</strong>에서 이미 발생한 문제였다.


<br />

## 해결 1: 이미지 사이즈 설정 변경

이 방법은 아직 상품을 대량 등록하기 전이거나, 앞으로 등록할 이미지 품질을 미리 안정화하고 싶을 때 유효하다.

<img width="70%" alt="Image" src="https://github.com/user-attachments/assets/6ac3d6b6-af64-4b2b-a37a-aeac0c2424d9" />

카페24 관리자에서 <strong>이미지 사이즈 변경</strong>을 열어 사진처럼 <strong>목적별 크기를 설정</strong>할 수 있다.

<strong>각 사이즈는 원본 이미지보다 같거나 작은 가로, 세로 값을 입력한 뒤 저장</strong>해주어야 한다.

아래와 같이 설정해주었다.
(목록이미지를 크게 한 이유는, 많은 목록을 한번에 불러오는 페이지에서도 큰 부하가 없었기 때문에 기본값 300보다 큰 사이즈로 설정하여 고화질로 보이도록 하기 위해서이다.)

```js
원본 이미지 크기: 640 x 768

상세 이미지: 640 x 768 (원본값)
목록 이미지: 640 x 768 (원본값)
작은목록 이미지: 100 x 100 (기본값)
상세 이미지: 220 x 220 (기본값)
확대 이미지: 500 x 500 (기본값)
```

이 작업을 한 뒤부터 새로 등록되는 이미지는 깨짐 없이 정상적으로 적용된다.

<br />

작업 순서

1. 이미지 사이즈 변경 버튼을 연다.

2. 원본보다 작은 적절한 가로, 세로 값을 입력한다.

3. 저장한다.

4. 그 이후 등록하는 상품 이미지는 정상 비율로 다시 생성되도록 한다.

<br />

## 해결 2: 이미 등록된 상품은 개별이미지로 다시 등록

이 방법은 이미 상품을 등록한 경우에 사용할 수 있다.

<img width="100%" alt="Image" src="https://github.com/user-attachments/assets/49a51f6b-799d-4b5f-9d79-0272d9c5cb47" />

이전의 이미지 사이즈 설정값으로 등록된 상품의 경우 <strong>[해결 1]을 먼저 적용한 후 상품별로 이미지를 다시 등록</strong>해야 한다.

<br />

작업 순서

1. [해결 1]을 먼저 적용한다. (상품 정보 저장까지 한 후에 다시 창을 열어야 함.)

2. 상품 이미지 등록 방식을 <strong>대표이미지 등록</strong>에서 <strong>개별이미지 등록</strong>으로 바꾼다.

3. <strong>상세 이미지</strong>, <strong>목록 이미지</strong>에 원본 이미지를 다시 각각 등록한다.

4. 저장한다.

즉, 이미 비정상적으로 저장된 상품은 사이즈 설정을 변경 및 저장한 후에 개별이미지 등록으로 다시 이미지를 서버에 저장되도록 하는 작업이 필요했다.

<br />

## 정리

- <strong>대표이미지 등록</strong>: 한 장의 원본으로 상세, 목록, 작은목록 이미지를 자동 생성한다.

- <strong>개별이미지 등록</strong>: 상세 이미지, 목록 이미지, 축소 이미지를 각각 따로 넣을 수 있다.

- 새 상품을 등록하기 전이라면 먼저 <strong>이미지 사이즈 변경 설정</strong>을 점검한다.

- 이미 등록된 상품에서 해상도 깨짐이 보이면 사이즈 변경 설정을 점검 후 <strong>개별이미지 등록</strong>으로 다시 이미지를 덮어쓴다.

<br />

## 느낀 점

- 처음에는 홈페이지에서 이미지가 흐리게 보여서 프론트 쪽 문제나 원본 이미지 문제를 먼저 떠올렸는데, 실제로는 관리자에서 목적별 이미지가 잘못 생성된 경우라는 점이 의외였다.

- 카페24는 상품 등록이 편리한 대신, 대표이미지 등록처럼 자동화된 기능이 잘못 동작하면 문제 원인을 늦게 찾을 수 있다는 점도 느꼈다.

- 앞으로 비슷한 문제가 생기면 CSS 부터 수정하려고 하기보다, 관리자에서 실제로 어떤 크기의 이미지가 저장됐는지부터 먼저 확인해야겠다고 느꼈다.
